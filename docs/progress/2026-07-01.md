### investigacion_amplia v2.0

**Cambios críticos:**
- Nueva tool `get_sector_corpus` — reemplaza `search_corpus_inta` (OR, sin límite, todos los docs)
- Nueva tool `search_corpus_conicet` — busca en CONICET vía `motor_api.buscar` (semantic, limit=100)
- Nueva tool `fetch_paper_full_text` — texto completo por doc_id para determinar TRL
- `fetch_page_text` degradada a secundaria (solo actores comerciales, no descubrimiento)
- `search_literature` mantiene max_results=15 por defecto, maneja error sin abortar

**System prompt v2.0:** workflow obligatorio de 8 pasos:
1. expand_agrovoc → 2. get_sector_corpus → 3. search_corpus_conicet →
4. análisis integral → 5. fetch_paper_full_text para TRL → 6. search_literature →
7. fetch_page_text (opcional) → 8. submit

**Pre-flight check (antes del loop LLM):**
- Bloqueante: INTA=0 docs para términos del sector
- Bloqueante: CONICET < 100 fichas
- Advertencia (no bloqueante): OpenAlex caído
- Si bloqueante → `raise RuntimeError` → motor captura → `MotorResult(status="stop")`

**Schema enriquecido:**
- `mapa_candidatos` ahora incluye `estado_de_desarrollo` (idea/lab/piloto/comercial/a-confirmar)
- `mapa_candidatos` incluye `papers_fuente` (IDs/títulos de papers)
- `informe_completo` requiere sección "Fuentes y cobertura" con N papers procesados por fuente

**Version:** 2.0 (INPUT_CONTRACT/OUTPUT_CONTRACT actualizados)

### Migración INTA → corpus_cientifico

- Script nuevo: `criza/ingest/migrate_inta_to_corpus.py` — copia `documento`
  (agente='harvest') → `ficha/corpus_cientifico` con embeddings BGE-m3, idempotente
  (dedup por `identifier`), no toca `documento`.
- Dry-run (1,643 registros) → prueba real de 50 (299.8s, $0,13 en Modal) → full run.
- **Resultado final: 1,643/1,643 migrados, 0 errores.**
- Costo total Modal del día: $0,17 (CONICET harvest ~380 llamadas + prueba de 50 + full
  de 1,593 restantes). Confirmado: el servicio es CPU-only (`services/bge-m3/modal_app.py`,
  cpu=2/mem=4096, sin GPU) con `scaledown_window=300` — Modal cobra tiempo de contenedor
  activo, no por request, por eso el costo no escaló linealmente con la cantidad de llamadas.

### Gap de diseño encontrado y cerrado: filtro por organismo de origen

Pregunta de Sebas: con INTA y CONICET (y CREA a futuro) en la misma área, ¿se puede acotar
una búsqueda semántica a un organismo específico? Respuesta con código: no — `motor_api.buscar()`
no tenía parámetro de filtro por props, y esa pregunta nunca se había hecho explícitamente en
`CONICET_CONNECTOR_GATE.md` §5 (decisiones A-E). Gap real de diseño, no decisión tomada.

Cerrado hoy:
- `motor_api.buscar()` (Capa 1, `knowledge_module/motor/api.py`) suma parámetro opcional
  `filtro: dict` — genérico, filtra por cualquier campo de props, no hardcodea "repositorio".
  Compatible hacia atrás (default `None`).
- `investigacion_amplia.py`: tool `search_corpus_conicet` → renombrado `search_corpus_cientifico`,
  acepta `repositorio: list[str]` opcional. `source` en la respuesta ya no hardcodea "CONICET".
- PASO 3 del workflow del agente ajustado: ahora excluye INTA explícitamente (ya cubierto
  exhaustivo por `get_sector_corpus` en el paso 2) para no releer los mismos papers dos veces
  ni gastar de más — directamente motivado por el razonamiento de Sebas sobre costo/precisión.
- Verificado con query real post-migración: `buscar()` sin filtro devuelve INTA+CONICET
  mezclados y ordenados por similitud; con `filtro={"repositorio": ["INTA"]}` o `["CONICET"]`
  devuelve solo lo pedido. Funciona correctamente.
- `DESIGN_GATE.md` — decisiones #10 (migración INTA) y #11 (filtro por repositorio) agregadas.
- Tests, `agents.md` actualizados con el nuevo nombre de tool y las cifras finales.
