### AGROVOC — `criza/utils/agrovoc.py` (completo)

Análisis y build del cliente canónico AGROVOC para resolución de términos del tesauro FAO.

**Contexto:** INTA indexa su material con términos AGROVOC. Usar los términos correctos del tesauro aumenta
la precisión de búsqueda en INTA, AGRIS y cualquier repo que use AGROVOC como vocabulario controlado.

**API:**
- Endpoint: `https://agrovoc.fao.org/browse/rest/v1/agrovoc` (Skosmos REST — el SPARQL endpoint timeout)
- Funciones: `/search`, `/label`, `/broader`, `/narrower`, `/related`
- Rate limit: ~1 req/seg. Configurable via `_RETRY_DELAY`.

**Funciones implementadas:**

| Función | Qué hace |
|---|---|
| `search(term, lang)` | Lista de conceptos que coinciden |
| `get_labels(uri)` | Labels ES + EN + PT para un URI |
| `expand_term(term, lang, top_n)` | Expansión completa: prefLabel ES/EN + broader/narrower/related |

**Comportamiento de `expand_term`:**
1. Busca en ES (requiere tildes exactas para algunos términos)
2. Si no encuentra, fallback a EN (para términos sin tilde o en inglés)
3. Retorna None si no hay resultados en ningún idioma

**Rate limiting:** retry exponencial en 429 (3 intentos, 3s × intento). Delay base de 0.3s entre requests.

**Nota de comportamiento:** AGROVOC es case-insensitive pero sensible a tildes en algunos términos.
"garrapata" y "hongos entomopatogenos" funcionan sin tildes. "control biológico" requiere la ó.
El agente científico pasa términos extraídos por Claude (con tildes correctas), por lo que esto no
es un bloqueante en el flujo automatizado.

**Flujo:**
1. `harvest(set_id, from_date)` → OAI-PMH → lista de records
2. Por cada record: si `--con-pdf` y open access → `get_pdf_url()` → `download_and_extract()`
3. `store_fuente_externa()` → KM (idempotente por `fuente_url`)
4. Imprime progreso cada 50 records + los primeros 5

**Uso:**
```bash

# Solo un instituto
python criza/ingest/harvest_inta.py --set biotecnologia

# Solo docs recientes + con PDF
python criza/ingest/harvest_inta.py --desde 2024-01-01 --con-pdf

# Simular sin escribir al KM
python criza/ingest/harvest_inta.py --dry-run
```

### batch_store_fuentes_externas — ON CONFLICT DO NOTHING

El approach original (SELECT pre-fetch + INSERT) tenía race condition: dos procesos concurrentes
(bhyvfgn90 y bjaqctuo1 background tasks de la sesión anterior) habían insertado registros
mientras se corría el nuevo harvest, causando UniqueViolationError.

**Fix:** reescritura completa de `batch_store_fuentes_externas` usando `pg_insert().on_conflict_do_nothing()`.

```python
stmt = (
    pg_insert(Documento)
    .values(rows)
    .on_conflict_do_nothing(
        index_elements=["fuente_url"],
        index_where=text("fuente_url IS NOT NULL"),  # partial index
    )
    .returning(Documento.id)
)
```

- Atómico: elimina race conditions
- `RETURNING id` cuenta los creados reales (no los que conflictuaron)
- `skipped = len(records) - created - errors` cuenta todo lo que no se insertó

**Tests:** 8/8 pasando (`knowledge_module/tests/test_batch_store.py`)

**Decisiones de diseño cerradas (7):**
| Decisión | Qué | Por qué |
|---|---|---|
| A | Flujos en YAML | Legibles, versionables, editables sin código |

| E | `pipeline_status` en KM después de cada paso | Recovery + transparencia |
| F | Gates humanos declarados en YAML | Flexibles por instancia, no hardcodeados en motor |
